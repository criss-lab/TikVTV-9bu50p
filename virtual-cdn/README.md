# Virtual CDN pilot (not deployed or wired into the player)

This isolated Node 20+ proof of concept does not modify Flutter, Android TV, the website, catalogue or payment flow. It must not be exposed publicly until reviewed and tested.

Configure CACHE_ACCESS_TOKEN (random 32+ characters), CHANNELS_JSON (explicit channel IDs, HTTPS URL, allowedHosts array, redistributionApproved=true only with documented authorization), PORT and optional CACHE_MAX_BYTES/CACHE_MAX_OBJECT_BYTES. Example CHANNELS_JSON: {"demo":{"url":"https://media.example.org/live/index.m3u8","allowedHosts":["media.example.org"],"redistributionApproved":true}}. Run: node virtual-cdn/server.mjs. Requests: GET /hls/demo/index with Authorization: Bearer <token>.

Properties: in-memory bounded LRU-like segment cache (64 MiB default), 30-second segment TTL, two-second playlist TTL, concurrent identical upstream fetch coalescing, 10-second upstream timeout, HTTPS and same-origin HLS asset restriction, explicit origin host allowlist, no URL-proxy parameter, no logging of bearer tokens. This is a single-instance cache; cross-instance sharing requires an approved shared object store. Live manifest URI rewriting is a pilot, not yet tested against every HLS variant (e.g. LL-HLS, byte ranges, redirects, DRM, encryption, discontinuities). Never enable for third-party playlists without rights. Do not cache personalized or credential-bearing streams.

Before production: integrate server-verified per-viewer entitlement instead of the pilot static bearer token, remove/avoid token leakage through media clients, validate DNS/IP against SSRF including private IP and DNS rebinding, support HLS redirect/variant and byte-range semantics, implement graceful shutdown, request/rate limits, health and metrics, test with licensed streams and real phone/TV devices, and deploy behind HTTPS. A cache reduces duplicate origin requests; it does not eliminate viewer egress costs or guarantee zero buffering.
